Scaffold a Nous Email Evaluator

Boss, you have created the project yourself. Next you will make one direct Nous request, print its raw output, and use that trace—not guesswork—to decide what to evaluate.

24 September 2026 · Course Lesson 2 · Working artifact: projects/nous-email-evals/

1 · What we are building today

A minimal, direct client. One fixed email goes to a model selected in your Nous Portal; one untouched summary comes back. This is a baseline trace, not yet a score or evaluator.

Nous, not OpenAI

Your key is sent only to the Nous inference endpoint. We use plain httpx, so the code does not depend on the OpenAI Python SDK or an OpenAI account.

Why the task is still an email summarizer

It is small enough to inspect by eye. Later we can test concrete requirements such as a sender field, key request coverage, and no invented facts.

In plain terms: before checking whether a POS terminal gives correct receipts all day, make one payment and keep the first receipt. The first raw model output is that receipt.

3 · The Nous request contract

Nous provides an OpenAI-compatible HTTP shape, but this lab calls it directly. “Compatible” describes the request format; it does not mean you are using OpenAI.

PieceValue in this labReason
Base URLhttps://inference-api.nousresearch.com/v1The stable API prefix; the program adds /chat/completions.
AuthenticationAuthorization: Bearer <NOUS_API_KEY>The key proves the request is allowed. It must stay in the terminal environment.
ModelNOUS_MODELCopy the current exact ID from your Nous Portal. Do not hard-code a tutorial model: availability and supported parameters vary.
HTTP libraryhttpxIt makes the URL, headers, and JSON request visible while you are learning.
Secret rule: never paste a real key into main.py, Git, a screenshot, this report, or chat. A key grants access; treat it like a bank-card PIN.

4 · Set the two terminal-only variables

In the terminal already inside projects/nous-email-evals, set the variables below. Replace only the values in quotes. The model ID comes from the Nous Portal model list.

export NOUS_API_KEY="paste-your-Nous-key-here"
export NOUS_MODEL="copy-the-exact-model-ID-from-Nous-Portal"

What export means

It creates an environment variable for this terminal session and programs started from it. Closing the terminal removes it.

Why two variables

The key is secret; the model ID is configuration. Keeping both outside the code lets you change providers or models without editing the program.

Do not run a model yet if you have not chosen an ID: open the Nous Portal, copy one available text model ID exactly, then return here. The public catalog changes, so an old model name can fail even when the code is correct.

5 · Type your first direct request

Create main.py yourself in this folder. This version sends one fixed email, prints the raw response, and gives clear errors without ever printing the key. It intentionally avoids an evaluator until we see real output.

import os
import sys

import httpx

BASE_URL = "https://inference-api.nousresearch.com/v1"

api_key = os.environ.get("NOUS_API_KEY")
model = os.environ.get("NOUS_MODEL")
if not api_key or not model:
    raise SystemExit("Set NOUS_API_KEY and NOUS_MODEL in this terminal first.")

email = """Hello support team,
My account is locked after I changed phones.
Please reset my access and tell me when I can sign in again.
Thanks, Ada"""

payload = {
    "model": model,
    "messages": [
        {
            "role": "system",
            "content": "Summarize the email in two short bullet points. Name the sender.",
        },
        {"role": "user", "content": email},
    ],
    "max_tokens": 160,
}

try:
    response = httpx.post(
        f"{BASE_URL}/chat/completions",
        headers={"Authorization": f"Bearer {api_key}"},
        json=payload,
        timeout=60,
    )
    response.raise_for_status()
except httpx.HTTPStatusError as error:
    print(f"Nous returned HTTP {error.response.status_code}", file=sys.stderr)
    print(error.response.text, file=sys.stderr)
    raise SystemExit(1)
except httpx.RequestError as error:
    raise SystemExit(f"Could not reach Nous: {error}")

answer = response.json()["choices"][0]["message"]["content"]
print(f"MODEL: {model}")
print("\n--- RAW MODEL OUTPUT ---")
print(answer)
Why no temperature yet? Nous model capabilities vary. This first call uses only the basic fields. After we inspect your selected model and trace, we can deliberately set the supported sampling controls for a fairer repeated-run evaluation.

6 · Run, then preserve the first trace

Save main.py, then run it once. If an answer prints, do not refine the prompt yet.

uv run python main.py

# After checking the output contains no private information:
mkdir -p traces
uv run python main.py | tee traces/first-run.txt

If an answer prints

Return the model ID and output only. That is your first trace. We will inspect it before defining a pass condition.

If it errors

Return the error text without the key. Common early causes are a missing terminal variable, an unavailable model ID, depleted credits, or a network problem.

Why save twice? The first run proves connectivity. The second command writes the same kind of raw output into a named file, creating an auditable trace that later evaluation can use.
