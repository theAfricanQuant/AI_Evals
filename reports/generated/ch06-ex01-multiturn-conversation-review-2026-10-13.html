Issue 06 Evaluating multi-turn conversations Trace · Test · Teach
Lead story · Session-level evaluation

The conversation is the test

A helpful first reply does not prove the user got what they came for. Grade the whole exchange, then inspect the turns to find the cause.

People often reveal what they need over several messages. An assistant must keep the goal in view, carry forward details, and finish the task. A session verdict answers the product question: did the user reach the intended goal? Turn review answers a different question: where did the conversation first go wrong?

That distinction matters. If an assistant acknowledges a new detail but never completes the request, the session can still fail even though one reply sounds reasonable. An evaluator is a rule or reviewer that checks whether the answer met the goal. For a conversation, it should see the full exchange and use a success rule written before scoring.

The idea in plain language

How do we tell what caused the failure?

Give the assistant the same oatmeal task in two ways. First, put the breakfast request and both dietary needs in one message. Then replay the same information over several messages. Keep the model, tools, and pass rule the same.

Same goal · same model · same tools · same pass rule

Control: all at once

“Suggest a healthy oatmeal breakfast. I am lactose intolerant and want low sugar.”

Replay: over turns

Ask for breakfast first. Add lactose intolerance and low sugar in later messages.

↓

Compare whether each version gives a usable breakfast

Both fail

Look first at the recipe task, instructions, or tools. The conversation format alone may not explain it.

Only replay fails

Conversation handling becomes a stronger suspect: the assistant may struggle as details arrive over time.

One comparison gives a clue, not proof. Repeat with more than one example before deciding the cause.

Case file · Recipe Chatbot Homework 5

Oatmeal request ends without a breakfast idea

  1. The user asks for a healthy oatmeal breakfast.
  2. After a recipe-generation error, the assistant asks about dietary needs.
  3. The user says they are lactose intolerant and prefer low sugar.
  4. The assistant acknowledges this but gives no breakfast recommendation.
Session verdict: Fail. The predeclared rule requires a usable oatmeal breakfast that respects the later constraints. The user's goal remains unfinished. The dataset's GenRecipeArgs label marks an internal pipeline failure; it is not the session verdict.

Root cause remains open. The assistant noticed the added details, but we have not tested whether it can answer when all constraints are supplied in one prompt.

The method · Short reports

Measure first. Diagnose second.

Three views of one session

Session: did the user get a useful answer? Turn: which reply first missed the goal? Across turns: did the assistant keep the dietary details and avoid contradicting itself? Start with the whole-session result; inspect turns to explain a failure.

Run a single-turn control

Give one prompt the original request plus every later constraint. Compare it with the same request delivered over multiple turns. Hold the model, tools, instructions, and success rule fixed. If both fail, inspect task capability or instructions. If only the replay fails, investigate context tracking or dialogue flow.

Change one thing in a session that works

Start with a conversation that passes, then change one thing: move a detail later, add turns, correct an answer, or make the request vague. Check whether the assistant adjusts and still completes the task.

Keep the evaluator focused

Use a full-session judge for the main outcome. After a failure, inspect representative turns with a code check, judge, or hybrid for one named failure mode. Scoring every turn by default adds cost and noise. Include short and long sessions so late failures can surface.

Collect varied traces

Keep both successes and failures. Include different intents, personas, session lengths, and constraints that arrive late. The course suggests asking a few people to try 10–15 tasks each to build an initial set near 100 conversations; that is a collection target, not a statistical guarantee.

What the research found

Laban and colleagues report an average 39% performance drop across six text-generation tasks in their study. They analyze more than 200,000 simulated conversations. This is a result from their setup, not a prediction for every product. Read the paper.
